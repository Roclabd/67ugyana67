# Сверка отчёта анализаторов

Требуется Python 3.10 или новее. Для запуска из корня репозитория передайте JSON-отчёт анализаторов в [формате авторов набора](../../fixtures/training/docs/submission-format.md).

```powershell
python tools/evaluator/evaluate.py report.json --markdown metrics.md
```

Оценщик выводит Markdown в консоль. Параметр `--markdown` также сохраняет его в файл в UTF-8. По умолчанию используется [учебный эталон](../../fixtures/training/ground-truth/training-findings.json). Для другого проекта или вариации передайте свой эталон с массивом `findings` и необязательным массивом `controls`.

```powershell
python tools/evaluator/evaluate.py report.json --truth variant-findings.json --markdown metrics.md
```

Валидное сравнение возвращает код `0` при любых метриках. Некорректный вход или ошибка чтения либо записи возвращают код `2` с диагностикой в stderr.

## Правила сверки

- Категория и основной путь должны совпасть. Разделители `/` и `\` эквивалентны, регистр сохраняется. Пустые компоненты пути и `.` убираются.
- В SECRET и SAST нужен точный `class` и пересечение включительных диапазонов. Если `endLine` пропущен, диапазон состоит из одной строки. Диапазон в отчёте допускает до 15 строк. Оценщик сверяет основное место из `path`, `line` и `endLine`. `alternateLocations` и `classAliases` служат для справки.
- В SCA нужны точные `group`, `artifact` и `version`, включая написание версии. `advisoryId` должен входить в массив `advisoryIds` эталона. Все SCA-находки входят в класс `known-vulnerable-dependency` для разбивки метрик.
- Каждая строка отчёта может совпасть с одной записью эталона, и наоборот. Оценщик максимизирует число пар. При равнозначных вариантах обработка следует порядку записей во входных файлах. Повторы сверх числа подходящих записей считаются FP.

В отчёте есть общие метрики, строки по категориям и классам, списки лишних и пропущенных находок. Precision равен TP / (TP + FP), recall равен TP / (TP + FN). Прочерк означает нулевой знаменатель. В деталях выводятся только поля сопоставления.

## Контроли и ловушки

Контроли проверяются по тем же полям, что и находки. Для SCA-контроля авторов набора учитываются также эквивалентные идентификаторы из [учебного справочника](../../fixtures/training/vulnerability-database/vulnerabilities.json). Контрольные срабатывания считаются отдельно от TP, FP и FN. Если один диапазон пересекает одновременно положительную находку и контроль того же класса, отчёт покажет и совпадение, и контрольное срабатывание.

Для оригинального эталона дополнительно проверяются любые SECRET-находки на строках `RepairAccounts.kt:17` и `LegacyIntake.kt:31` и любые SCA-находки для координат `org.yaml:snakeyaml` и `org.jetbrains.kotlin:kotlin-stdlib`. Обе транзитивные зависимости образуют одну ловушку с отдельным срабатыванием на каждую строку отчёта. Для вариаций используются только контроли из переданного эталона.

## Проверка

```powershell
python -B -m unittest discover -s tools/evaluator -v
python tools/evaluator/evaluate.py fixtures/training/docs/training-result-example.json
```

Пример авторов набора содержит три из 15 ожидаемых находок. Итоговые метрики для него составляют 3 TP, 0 FP, 12 FN, precision 100%, recall 20%, без срабатываний на контролях и ловушках.
