# Экспорт отчётов

`DefaultReportExporter` регистрируется как Spring-компонент и формирует JSON авторов набора и Markdown из одного внутреннего отчёта. JSON содержит только поля формата авторов набора. Находки сортируются, повторы объединяются, а CVE и GHSA одной записи приводятся к идентификатору из справочника. [Контракт отчёта](../../../contracts/report-format.md)

Markdown показывает находки, покрытие каждого анализатора, причины пропусков и статус AI. Для SECRET используются маска и фиксированные описания.

Тест `C5IntegrationTest` прогоняет SECRET и SCA на Service Desk. Для проверки через evaluator укажите путь записи JSON в переменной `C5_EVALUATOR_REPORT` и запустите задачу `:backend:analyzers:test`.

## Карта маршрутов

Нода `output.route-map` принимает `model` типа `PROJECT_MODEL` и возвращает артефакт в порте `report` типа `REPORT`. Результат виден в данных ноды запуска. Он включает JSON-строки маршрутов и готовый Markdown.

Карта показывает HTTP-метод, путь, первое статически сопоставленное правило Spring, последующие применимые декларации той же цепочки, аннотации метода и установленные связи с таблицами и колонками владельцев. Для динамических правил, неоднозначных цепочек и неразрешённых связей карта сохраняет статус `unresolved`. Используются статически известные декларации и вызовы функций проекта. SQL-текст и значения параметров в артефакт не входят.

Связи с таблицами учитывают `JOIN` и вызовы методов проекта через переменные с явно указанным типом, например внедрённый в контроллер сервис. Если тело обработчика возвращает только литерал или список литералов из стандартной библиотеки, карта указывает `tableEvidence: located` и пустой массив `tables`. Поле правила `access` сохраняет имя операции, а `accessText` содержит исходное выражение доступа, включая аргументы.
