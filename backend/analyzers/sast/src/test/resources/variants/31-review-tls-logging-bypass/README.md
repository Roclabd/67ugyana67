# TLS: логирование вместо проверки

- Находка: `SupplierClients.kt:15`. Верификатор логирует имя и всегда принимает его.
- Находка: `SupplierClients.kt:25`. Установленный через SSLContext trust manager только логирует размер цепочки; сертификаты не проверяются. Стандартная проверка hostname не восстанавливает проверку доверия цепочке.
- Контроль: `SupplierClients.kt:36`. Делегирование штатному hostname verifier без изменения проверки цепочки.
- Причина FN: `TlsVerificationRule.alwaysTrue` требует единственный оператор `true`, а `bodyIsEmpty` допускает только пустое тело/пустой return. Безвредное логирование ломает оба шаблона распознавания.

Проверено на текущих исходниках анализатора: FN=2, FP=0, контроль проходит. `expected.json` описывает правильный результат, поэтому этот регрессионный тест сейчас должен падать.
