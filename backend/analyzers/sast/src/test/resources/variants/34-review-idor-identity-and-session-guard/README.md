# IDOR: использование личности и настоящая проверка

- Находка: `TicketController.kt:38–40`. Любой вошедший клиент выбирает произвольный ticketId. Principal используется лишь в журнале; JPA findById не ограничен владельцем.
- Контроль: `TicketController.kt:46–50`. После JDBC-загрузки owner сверяется с authentication.name из серверной Spring Security сессии. Чужая строка не возвращается; require прерывает выполнение.
- Причина FN: `ObjectAuthorizationRule.identityUse` считает любое использование Principal достаточной защитой и прекращает анализ эндпоинта.
- Причина FP: ownerCheck — регулярное выражение по тексту; сравнение `row["customer_id"]` с личностью из HttpSession не распознаётся.

Проверено на текущих исходниках анализатора: FN=1, FP=1, попаданий в контроль=1. `expected.json` описывает правильный результат, поэтому этот регрессионный тест сейчас должен падать.
