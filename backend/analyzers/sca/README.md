# Проверка зависимостей

Нода `analyzer.sca` принимает модель проекта через порт `model` и возвращает находки через `findings`. Она сверяет явно объявленные Gradle-зависимости со справочником Maven, который сборка включает в ресурсы без изменения исходного файла. Lockfile уточняет версии объявленных зависимостей.

Модель определяет версию по применимому lockfile, объявлениям и встроенным таблицам Spring Boot BOM `3.5.8` и `4.0.9`. При однозначном `enforcedPlatform` используется версия BOM, в том числе при явной версии в Gradle. Анализ выполняется офлайн по Gradle Kotlin DSL. Релиз и строка подключения доступны в `coverage.springBootBoms`, Markdown и доказательстве находки. Неизвестный релиз и конфликтующие или неоднозначные настройки попадают в `coverage.unresolved`. Если неопределённость мешает проверить зависимость из справочника, SCA возвращает `PARTIAL` и сохраняет подтверждённые находки.

Нода также читает `vulnerabilities.json` в любой папке снимка. Дополнительные справочники загружаются в порядке путей и заменяют предыдущие записи с тем же ID. `coverage.advisorySources` перечисляет загруженные справочники и количество записей в каждом. `coverage.advisoryCount` показывает итоговый размер после объединения. При ошибке в справочнике проекта проверка продолжается по доступным справочникам со статусом `PARTIAL`. Путь и причина видны в `coverage.filesSkipped`.

Числовое сравнение считает `1.9` и `1.9.0` равными. Нижняя граница диапазона не может быть выше верхней. При равных границах обе должны включать указанную версию. Ошибка границ приводит к пропуску справочника целиком.

В отчёте сохраняется исходная запись версии. Для каждой подходящей записи выдаётся отдельная находка с критичностью, исправленными версиями и местами, где объявлена зависимость и установлена её версия. Если точную версию не удалось установить, она отражается в `coverage.unresolved`. Неопределённость по зависимостям, представленным в справочнике, даёт `PARTIAL`.

Покрытие SCA группирует разобранные объявления зависимостей по трём результатам: версия сверена со справочником, версия известна и в справочнике нет записей, версия не установлена или не поддерживается. В Markdown-отчёте также указана дата каждого снимка справочника, если её передал источник.

## Своя политика версий

Нода `analyzer.sca.custom` «Своё правило SCA/конфигурации» получает `model` от ноды «Разбор проекта» и передаёт совпадения через `findings`. Добавьте по одной ноде на проверяемые координаты и диапазон. Правило проверяет явно объявленные Gradle-зависимости по разобранной модели проекта.

| Параметр | Значение |
| --- | --- |
| `coordinate` | Точные Maven-координаты `group:artifact`. |
| `lowerVersion` | Необязательная нижняя граница. |
| `upperVersion` | Обязательная верхняя граница. |
| `lowerInclusive`, `upperInclusive` | Включение границ. По умолчанию нижняя включена, верхняя исключена. |
| `severity` | `LOW`, `MEDIUM`, `HIGH` или `CRITICAL`. По умолчанию `MEDIUM`. |

Границы задаются числовыми версиями, например `1.2` и `2.0`. При таких границах и настройках по умолчанию версия `1.2.0` попадёт в находки, а `2.0` окажется вне диапазона. Если версия нужной зависимости неизвестна, в покрытии будет `PARTIAL` с причиной. В отчёте совпадение привязано к объявлению зависимости и идентификатору локальной политики `POLICY-…`.
