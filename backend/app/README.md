# backend/app

REST, SSE, хранилище сценариев и запусков, шифрование секретов нод, CI, шаблоны и раздача фронта.

Из корня репозитория запустите `./gradlew :backend:app:bootRun` с JDK 21. На Windows используйте `.\gradlew.bat :backend:app:bootRun`.

Сервер по умолчанию слушает `http://127.0.0.1:8080`. H2 хранит данные в `data/workflow.mv.db`. Если `frontend/dist` уже собран, Gradle включает его в JAR; иначе доступно API.

Создайте сценарий с `trigger.manual`, передайте его порт `trigger` в `source.archive` или `source.repo` и подключите сканеры через порт `workspace`. Для загрузки ZIP отправьте поле `file` на `/api/uploads`, затем передайте полученный `uploadId` в `POST /api/workflows/{id}/run`. Ход запуска доступен в `GET /api/runs/{runId}/events`.

Настройки берутся из переменных окружения или корневого `.env` (формат properties, без кавычек вокруг значений). Для секретных полей нод нужен `APP_SECRETS_KEY`. Для CI нужны `CI_TOKEN`, `CI_RULES_VERSION`, публичный учебный репозиторий из `ALLOWED_REPOS` и Git с поддержкой `http.curloptResolve`. Параметры отправки Telegram и SMTP описаны в `.env.example`.

При остановке графа узлы доставки на активном маршруте получают уведомление «Проверка не выполнена, итог неизвестен». Попытка запуска по расписанию, которую сервер не смог запустить, остаётся в истории со статусом `FAILED` и причиной.

`GET /api/settings/llm` показывает провайдера, адрес, модель и признак наличия ключа. `PUT /api/settings/llm` переключает модель для текущего экземпляра приложения. При смене адреса ключ прежнего провайдера сбрасывается. При запуске используются настройки окружения или `.env`.

Сервер рассчитан на локальную демонстрацию и проверяет заголовок `Host`. По умолчанию разрешены `localhost`, `127.0.0.1` и `[::1]`. При развёртывании укажите используемые имена хостов в `APP_ALLOWED_HOSTS` и настройте авторизацию на прокси для API сценариев и запусков. Входящие вебхуки и CI проверяют токен на сервере.

Когда C и D добавят файлы сборки, Gradle включит их модули. Контракты для их бинов описаны в `contracts/node-spi.md`.
