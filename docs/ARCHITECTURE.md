# Архитектура

> Короткая схема решения для команды и для слайда. Обновлять по мере реализации.

```
Редактор графа (React Flow) ──сохранить──▶ Workflow
                                              │
Триггер: кнопка / cron / webhook / CI ──▶ Run
                                              │
Исполнитель DAG (корутины, топологический порядок)
   ├─ Источник: архив или клон учебного репо → рабочая папка
   ├─ Разбор проекта → ProjectModel (PSI, конфиги, Gradle, Spring, SQL)
   ├─ SECRET / SCA / SAST → Finding[] + coverage
   ├─ Объединить / фильтр / дедупликация / подсчёт
   ├─ If / сравнение / regex (выражения {{...}})
   ├─ LLM: находки → объяснения → валидатор
   ├─ Отчёт: JSON авторов набора + читаемый
   └─ Уведомление: Telegram / SMTP / webhook
        │
   SSE → живые статусы и данные нод в интерфейсе; Run сохраняется в историю
```

## Модули

| Модуль | Ответственность |
|---|---|
| `backend/engine` | модель графа, SPI, реестр, типы портов, `GraphValidator`, исполнитель, выражения |
| `backend/nodes` | триггеры, источники, логика, уведомления, экспорт отчёта |
| `backend/app` | REST, SSE, хранилище, секреты, CI, шаблоны |
| `backend/analyzers/model` | `ProjectModel` |
| `backend/analyzers/{secret,sca,report}` | правила SECRET и SCA, `ReportExporter` |
| `backend/analyzers/sast` | taint и правила SAST |
| `backend/ai` | LLM-клиент, промпты, валидатор, оценка полезности |
| `frontend` | редактор, выполнение, отчёты, шаблоны, настройки |
| `tools/evaluator`, `tools/mutator` | точность на эталоне и вариациях |
| `tools/sandbox` | изоляция для тестов-доказательств (необязательно) |

## Ключевые решения

- Разбор проекта отделён от правил: модель строится один раз, правила — отдельные классы.
- Нода = один класс по SPI; новая нода не требует правок движка и фронта.
- LLM только объясняет: набор находок определяют анализаторы, ответ модели проходит валидатор.
- Решения о допуске (статус CI, публикация шаблона, запуск сгенерированного сценария) принимает сервер.
- Неизвестное — не ноль: у каждого анализатора `COMPLETE / PARTIAL / FAILED` и `coverage`.

## Подключение и хранение

- Gradle Wrapper использует JDK 21. Модули `analyzers` и `ai` подключаются после появления их собственных файлов сборки.
- Каталог строится из Spring-бинов `workflow.engine.NodeDefinition`. Движок проверяет граф при сохранении и запуске, исполняет независимые ноды одного уровня параллельно и записывает публичные события SSE в H2.
- В H2 остаются версионированные сценарии, зашифрованные параметры, запуски, события и шаблоны. Рабочие папки запусков очищаются после завершения.
- Для CI проверяется SHA фактически полученного Git-снимка и версия правил в результате каждого анализатора. Если исходные данные или покрытие нельзя подтвердить, допуск закрыт.
